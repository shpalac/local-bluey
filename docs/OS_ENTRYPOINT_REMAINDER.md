## Original promise and delivered parser

Original [#91](https://github.com/shpalac/local-bluey/issues/91) asked for global Mac shortcuts/tray, iOS App Intents/Shortcuts/widgets and a small deep-link action set, through the same face request path, safety gate and action log. Its original acceptance required tested common paths, validation without silent denied/confirm-required actions, and documented supported actions/platform limits. The live issue is CLOSED with no comments; this audit does not reopen it or reinterpret closure as proof of every proposed native entry point.

Merged [PR106](https://github.com/shpalac/local-bluey/pull/106), head `60d43c6033152e90327976ca8725b7f51a96b5c7`, merge `f52de5d4c900559cfdb024b78cca2fc6b7de6038`, explicitly described Dart-side core with native hotkey/App Intents/widgets follow-up. Its five changed files supplied parser/tests, README and tray Ask/Mute/Status plus speech stop. The parser returned a value; neither its original code nor that delivery connected incoming URLs to a dispatcher.

Closed [#289](https://github.com/shpalac/local-bluey/issues/289) and merged [PR295](https://github.com/shpalac/local-bluey/pull/295), head `549e095bdf0e95feaf74290e58d04cfdfcbdb113`, merge `270eff5d5e22584465336d15ee76ca2eece15a52`, delivered strict parsing, not registration or runtime dispatch. Current [DeepLinks](../lib/services/deep_links.dart) and [seven unchanged tests](../test/deep_links_test.dart) accept only lowercase canonical `localbluey://action`, six actions, exactly one literal `text` key for ask and no query for others. They reject path/userinfo/port/fragment/query ambiguity, malformed percent/UTF-8, blank asks and limits beyond 8192 encoded ASCII code units/2048 decoded UTF-8 bytes. Valid English/Hebrew/emoji/spacing survives unchanged; `+` means space. Invalid input returns null, not a partial action. This validation is delivered, not duplicate backlog.

The file's old comments say "Validation + dispatch", "scheme the app registers" and "same request path". Its actual implementation has only constants and `parse`, returning `DeepLink`. No subscription, request, confirmation or log call exists there. Comments and allowlist membership are not runtime proof.

## Six parsed actions and actual runtime seams

**All six:** current source has no URL-to-action binding. The following are existing in-app paths, not proof the parsed URL triggers them or instructions to choose them automatically.

- **wake:** face/W-key `_setAwake(true)` in [main](../lib/main.dart) updates awake/face/tutorial/reaction and broadcasts wake to phone. Tray Ask directly sets awake and broadcasts; it does not call the full face helper or submit an ask. Phone wake packets set host awake directly. Choosing a common future path must account for these differences, not assume every current path identical. Wake alone does not start microphone capture.
- **sleep:** face/W-key `_setAwake(false)` updates face/state and broadcasts. Phone sleep changes host awake. Neither is automatically SafetyGate.kill or capture stop. [ToolExecutor](../lib/services/tool_executor.dart) `go_to_sleep` calls optional onSleep; current main does not assign that callback. Its injected unit callback is not mounted-host sleep proof. Any decision to reuse or repair this seam is separate work.
- **ask(text):** ordinary face/key/phone feeds an audio File to `_processUtterance` and [RequestRunner.process](../lib/services/request_runner.dart), not an existing text entry method. Phone [audio intake](../lib/services/phone_audio.dart) validates/stages audio, not arbitrary text. The runner loads providers, transcribes, records conversation/routine expansion, asks brain, authorizes each tool, executes/logs and speaks with generation/deadline guards. No text-to-runner API is delivered. Calling brain.ask directly would skip queue/safety/tool/conversation/speech orchestration, so it is not a safe inferred adapter.
- **stop:** tray Stop calls the same retained `_safety.kill()` plus hold-key reset. [SafetyGate](../lib/services/safety_gate.dart) synchronously sets killed/generation, isolates listener errors; main listener refreshes key cleanup, cancels key intent, publishes Stopped and resets brain. Runner discards old queued/admitted results at boundaries. This is not physical cancellation of every entered native/network call, nor implicit ScreenWatch.stop or SpeechService.stop. Watch has its separate stop item. URL "cancels every action immediately" is stronger than inspected proof.
- **mute:** delivered [SpeechMuteCaller](../lib/services/speech_mute_caller.dart) wraps actual SpeechService.stop with pending/join/error/explicit retry and each explicit tray event's immediate phone stopSpeech broadcast. That proves local owner/caller behavior, not phone receipt or OS URL ingress. No automatic retry, new phone timing or all-file/native erasure guarantee is selected.
- **status:** tray writes a bubble based on killed/awake; it is not a full permissions/watch/provider readiness report, does not Show the hidden window and does not answer a URL requester. Visibility/return-channel policy remains unselected. Status should not be treated as permission grant/readiness.

## Safety, logging, role and lifetime boundaries

Parser action allowlisting is syntactic validation only. Ask can result in risky tools. RequestRunner invokes SafetyGate.authorize before tools; main wires confirmation dialog/front-app/kill generation. Current enabled policy rejects denied target apps/allowlist violations and risky actions lacking confirmation; explicit persisted safety disable is existing user policy, not an excuse for a new entry point to bypass the retained gate. Pending confirmation and late stage results cannot revive a killed generation. No URL permission to reset Stop, enable watching/recording or change safety is implied.

[ToolExecutor](../lib/services/tool_executor.dart) records executed/error tool outcomes through [ActionLog](../lib/services/action_log.dart); denied calls go back to brain without executor execution. Wake/sleep/tray status/parser rejects have no common entry-point action-log receipt. ActionLog can retain a storage warning rather than prove durable logging. A future ingress receipt/log contract needs explicit selection, not a promise that every parsed action already reaches the log.

Phone home is behind [LockGate](../lib/ui/lock_gate.dart), Settings also gated; MacHome itself is not globally LockGate-wrapped. LockGate requires explicit retry after background lock and fences authentication results by lifetime/generation. No URL consumer exists to respect or bypass that gate. A future phone/host/unsupported or locked-route policy must be chosen before registering a scheme or dispatching. Source-only main wiring and injected owner/widget tests do not prove real authentication or OS delivery.

MacHome owns current caller lifetimes and disposal, while runner entered stages can finish underneath timeout/generation checks. There is no initial/resume URI queue, owned URL subscription, duplicate URI policy or disposed-handler fence to audit as delivered. Registering a scheme without these paths would still leave no common action completion/refusal channel. URI replay, unsafe role dispatch and late UI effects are source-derived design risks, not reproduced current failures.

### Proposed actual-boundary matrix

No tests below were added. An eventual selected implementation should use actual ingress/dispatcher/request owners with controlled held boundaries, not parser values relabeled runtime proof.

- **Initial and resumed URI:** startup-not-ready versus ready, one owned subscription, platform initial-event/stream duplication, burst/repeated-identical and different URI ordering. Manager chooses reject/queue/coalesce policy; no default replay or unbounded queue inferred.
- **Validation/refusal:** all current canonical parser cases unchanged; no calls/logged success on rejected links. Safe generic failure without URL payload/secrets; current failure versus superseded/disposed result explicit.
- **Role/lock:** Mac host, paired/unpaired phone, unsupported platform, pending/failed/background authentication. No host promotion, paired phone forwarding or lock bypass chosen silently; test actual LockGate/role boundary, not a bool-only substitute.
- **Actions:** wake/sleep face/state/broadcast semantics and no capture; Stop before/after request admission, held transcribe/brain/confirmation/tool and kill+resume; mute held local stop and exact selected phone broadcast count, no receipt claim; status visibility/return semantics explicitly selected.
- **Ask:** held active run, two existing queued audio slots/full refusal and mixed text/audio order if selected; generation discard between grant/entry; deadline/provider/routine/conversation/tool denial/confirmation/error/TTS. Preserve existing runner guarantees without duplicating or taking over366/372 owners.
- **Lifetime:** queued versus entered initial/resume operation, dispose/reentrant notification and duplicate subscriber removal, no later display or new owner effects; entered native work may finish.
