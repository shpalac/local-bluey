## What the 21 new tests show

Actual BrainHostState, HostReloadController, LocalOnlyPreferences, Brain, RequestRunner and WatchVision/ScreenWatch compose through existing seams. Both concrete OpenAI-compatible and Ollama providers use a network-forbidden BaseClient: it never delegates to an IO client, rejects unexpected methods/hosts/paths, records the actual finalized synthetic JSON and returns controlled SSE/NDJSON/nonstream responses. URLs are synthetic `https://retained.invalid/v1` and `https://replacement.invalid/v1`; model/text/audio/image values are synthetic, no credentials, real tool or model call. Request transcription/TTS are separate injected dependencies, not proof of their privacy or transport behavior.

- **Retained failure and fresh request:** actual current load/refusal failure after prior remote construction retains identical Brain/null refusal/remoteActive true, while controller shows failed and settled. Actual ordered privacy owner is verified ON. A later successful fresh-settings request calls the retained concrete streaming endpoint, not the different fresh request-settings endpoint; TTS fixture receives fresh settings. The provider performs no privacy-owner read. Fresh settings failure prevents transcription/HTTP entry and cleans the recording.
- **Selection time:** held transcription allows host replacement before the runner's lazy Brain selection, so the replacement endpoint is used. Replacement after intercepted stream entry does not change that entered call; the next request resolves the replacement. Both provider formats are checked separately.
- **Tool result:** actual retained Brain.toolResult invokes the concrete nonstream endpoint with a tool message, separately from streaming. No real tool is executed. Exact POST/URL/call count/nonstream shape are asserted; no retry/real transport experiment.
- **Watch:** current ON preference/session gates can reach the retained remote concrete nonstream URL without changing Brain history. Provider chosen before a held capture remains used after host replacement; the next operation resolves the new provider. Current preference uncertainty prevents new inference and stops the session; failed start throws typed uncertainty, and explicit recovered start works. Verified OFF or uncertainty at the second gate prevents provider entry after held capture. Null Brain, declined consent and false-local start refuse their respective entry paths. Stop/restart fences an entered mocked response and rejects the old WatchVision; a fresh session-bound instance works.

## Limits
